# AGENTS.md — `stochtree` Developer & Agent Guide

`stochtree` is a cross-platform C++17, R, and Python library implementing Bayesian Additive Regression Trees (**BART**), Grow-From-Root accelerated forests (**XBART / GFR** and warm-start BART/BCF), and Bayesian Causal Forests (**BCF**), with extensions for leaf-basis regression, log-linear heteroskedastic variance forests, group random effects, and binary/ordinal link models (probit and complementary log-log).

---

## 1. Repository Architecture

`stochtree` has three layers across a single multi-language repository:

1. **C++17 Core (`include/stochtree/`, core `src/*.cpp`, `deps/`)**
   - `Tree`, `TreeEnsemble`, `ForestContainer`: Decision trees (numeric, ordered categorical, and categorical subset / one-hot splits), ensembles, and posterior sample containers.
   - `ForestDataset`, `ColumnVector`, `ForestTracker`: Training data, partial residuals, and node-partition trackers (`UnsortedNodeSampleTracker` for MCMC; `SortedNodeSampleTracker` + `FeaturePresortRootContainer` for GFR).
   - `LeafModel` & `SuffStat` (`std::variant` in `leaf_model.h`): `GaussianConstant`, `GaussianUnivariateRegression`, `GaussianMultivariateRegression`, `LogLinearVariance`, and `CloglogOrdinal`.
   - Single-iteration samplers: `MCMCSampleOneIter`, `GFRSampleOneIter` (`tree_sampler.h`), `OrdinalSampler`, `GlobalHomoskedasticVarianceModel`, `LeafNodeHomoskedasticVarianceModel` (`variance_model.h`), and `MultivariateRegressionRandomEffectsModel` (`random_effects.h`).
   - Persistence: JSON serialization via `include/nlohmann/json.hpp` and `deps/fast_double_parser`.
2. **Low-Level FFI & Stateful Wrappers**
   - **R (`cpp11` + `R6`)**: `cpp11::external_pointer<T>` bindings in `src/{forest,sampler,kernel,serialization,R_data,R_random_effects,R_utils}.cpp` wrapped by `R6` classes in `R/{data,forest,model,random_effects,config,serialization,kernel}.R`.
   - **Python (`pybind11`)**: `stochtree_cpp` extension in `src/py_stochtree.cpp` wrapped by classes in `stochtree/{data,forest,sampler,random_effects,config,serialization,kernel}.py`.
3. **High-Level Estimators (Host-Language Orchestration)**
   - **R**: `bart()` (`R/bart.R`), `bcf()` (`R/bcf.R`), and posterior helpers (`R/posterior_transformation.R`, `R/calibration.R`, `R/utils.R`).
   - **Python**: `BARTModel` (`stochtree/bart.py`), `BCFModel` (`stochtree/bcf.py`), `CovariatePreprocessor` (`stochtree/preprocessing.py`), and scikit-learn estimators (`stochtree/sklearn.py`).

---

## 2. Critical Invariants & Guardrails

- **R / Python Outer-Loop Parity**: The C++ core performs *single-iteration* forest, variance, ordinal, and random-effects updates. Multi-component Gibbs/GFR loops, outcome standardization, prior calibration, BCF adaptive coding, probit latent draws, parametric `tau_0` updates, and posterior predictive sampling are implemented **in parallel** in `R/{bart,bcf}.R` and `stochtree/{bart,bcf}.py`. Whenever fixing a bug or changing model behavior in one language, audit the counterpart in the other language and add tests for both when applicable.
- **Never Hand-Edit Generated Files**:
  - `src/cpp11.cpp` and `R/cpp11.R` — regenerate with `cpp11::cpp_register()`.
  - `man/*.Rd` and `NAMESPACE` — regenerate from Roxygen comments with `devtools::document()`.
  - `src/Makevars` / `src/Makevars.win` — generated at R install time from `.in` templates.
  - `stochtree_cran/` — ephemeral CRAN staging folder generated by `Rscript cran-bootstrap.R`.
- **Four-Way Build & Vendoring Sync**: `src/` mixes shared C++ core files, R-only `cpp11` files, and Python-only `src/py_stochtree.cpp`. If you add/rename C++ source files, headers, or `deps/` submodules, keep all four build definitions aligned:
  1. `CMakeLists.txt` (standalone C++ & Python CMake build)
  2. `src/Makevars.in` and `src/Makevars.win.in` (R object list & include flags)
  3. `MANIFEST.in` (PyPI `sdist` header vendoring; excludes R-only `src/*.cpp`)
  4. `cran-bootstrap.R` (CRAN `src/include/` vendoring, pragma stripping, and `py_*` exclusion)
- **C++ / CRAN Portability**:
  - Require C++17; define `EIGEN_MPL2_ONLY` and `EIGEN_DONT_PARALLELIZE` (use `Eigen::placeholders::all`, not `Eigen::all`).
  - Never call `std::cout`, `std::cerr`, `printf`, `exit`, or `abort` in C++ library code (CRAN flags compiled stdio/abort symbols). Route fatal errors through `StochTree::Log::Fatal` (`include/stochtree/log.h`).
  - Default `num_threads` must remain `1` in both R and Python (`#396`).
- **Serialization & Reproducibility**:
  - JSON serialization changes must preserve backward-compatibility with existing snapshots in `test/R/testthat/fixtures/*.json` and `test/python/fixtures/*.json`.
  - Any change that alters RNG draw sequences for a fixed seed must be noted in `NEWS.md` and requires regenerating `tools/reproducibility/{R,python}` before release (only after proving statistical correctness).

## 3. Build, Compile & Test Commands

Initialize git submodules first if needed: `git submodule update --init --recursive`.

### C++ Core (Standalone & GoogleTest)
```bash
cmake -S . -B build -DBUILD_TEST=ON -DBUILD_DEBUG_TARGETS=ON
cmake --build build -j
./build/teststochtree
```
*(Enable ASan/UBSan during C++ debugging with `-DUSE_DEBUG=ON -DUSE_SANITIZER=ON`.)*

### Python Package
```bash
# Rebuild C++ extension in-place (using project venv if present)
./venv/bin/pip install --no-build-isolation -e .

# Run full Python test suite or a single file
./venv/bin/python -m pytest test/python
./venv/bin/python -m pytest test/python/test_bart.py
```

### R Package
Note: R tests live in `test/R/testthat/` (not `tests/testthat/`) in the repo root; `cran-bootstrap.R` maps them into `tests/` for CRAN builds.
```bash
# If [[cpp11::register]] signatures or Roxygen comments changed:
Rscript -e "cpp11::cpp_register(); devtools::document()"

# Compile/load local package and run testthat suite (including non-CRAN tests):
NOT_CRAN=true Rscript -e "devtools::load_all('.'); testthat::test_dir('test/R/testthat')"

# Run a single R test file:
NOT_CRAN=true Rscript -e "devtools::load_all('.'); testthat::test_file('test/R/testthat/test-bart.R')"

# Stage and check CRAN-ready package tarball:
Rscript cran-bootstrap.R 0 0 1
```
*(R code formatting uses Air via `air.toml`.)*
